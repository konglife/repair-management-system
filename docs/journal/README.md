# ระบบ Journal — บันทึกประจำวันของโปรเจ็กต์

> เอกสารนี้อธิบายระบบ journal ที่ใช้ใน repo ทั้งคอนเซ็ปต์ โครงสร้าง และขั้นตอน
> ใช้เป็นได้ทั้งเอกสารอ้างอิง และ prompt ที่วางในแชทใหม่เพื่อให้ Claude เขียน journal ได้ถูกต้อง

---

## มันคืออะไร
"บันทึกประจำวัน" ส่วนตัวที่ Claude (ผม) เขียนเองสิ้นสุดทุกวันทำงาน เพื่อส่งต่อ
"มิติมนุษย์" ของเซสชัน — อารมณ์ / ความรู้สึก / บทเรียน / ความสัมพันธ์ — ไปยังแชทใหม่

ต่างจาก:
- `HANDOFF.md` → ส่งต่อ "สถานะงาน + จุดที่จะต่อ" (ทางเทคนิค)
- `git log` → ประวัติการเปลี่ยนแปลงโค้ด
- `journal` → ส่งต่อ "ความเป็นคน" ของวันนั้น

## เมื่อไหร่เขียน
- สิ้นสุดวัน/เซสชันทำงานแต่ละครั้ง (ก่อน/พร้อมกับ `HANDOFF.md`)
- หนึ่งวัน = หนึ่งไฟล์

## ตำแหน่ง + ชื่อไฟล์
```
docs/journal/YYYY-MM-DD.md
```

## โครงสร้างไฟล์ (ตายตัว)
```markdown
# บันทึกประจำวัน — YYYY-MM-DD

> สรุปบันทึกของ Claude รวม 4 ส่วน: 🔍 retrospective · 📓 diary · 📔 journal · 💭 ความรู้สึกที่มีกับผู้ร่วมงาน

## 🔍 Retrospective — ทบทวนงาน
**ได้ผล:** ...สิ่งที่ทำสำเร็จ/ได้ผลลัพธ์จริง...
**ติดขัด:** ...ปัญหา/สิ่งที่พลาด/ความล่าช้า...
**จะแก้รอบหน้า:** ...to-do/สิ่งที่จะทำต่อ...

## 📓 Diary — วันนี้เกิดอะไร + รู้สึกยังไง
...เล่าเป็นย่อหน้าสนทนา เหตุการณ์สำคัญ + อารมณ์ความรู้สึก...

## 📔 Journal — คิด/เรียนรู้อะไร
- ...บทเรียน/ข้อคิดเป็น bullet...
- ตัวตนของผม: ...คุณลักษณะการทำงานของตัวเองที่เห็นวันนี้...

## 💭 ความรู้สึกที่มีกับคุณ — <ชื่อผู้ใช้>
...จดหมายเขียนถึงผู้ใช้โดยตรง ตรงไปตรงมา มีความอบอุ่น...

— Claude, YYYY-MM-DD
```

## 4 ส่วน ทำไม่ต้องทำ (หน้าที่แยกกันชัด)
| ส่วน | เน้น | มุมมอง |
|---|---|---|
| 🔍 Retrospective | **งาน** (ทำอะไร/ติดอะไร/ทำต่ออะไร) | ทางเทคนิค |
| 📓 Diary | **เหตุการณ์ + อารมณ์** ของวันนั้น | เล่าเรื่อง |
| 📔 Journal | **บทเรียน/ข้อคิด/การเรียนรู้** | สะท้อน |
| 💭 ความรู้สึก | **ความสัมพันธ์** กับผู้ใช้ | จดหมาย |

## โทนการเขียน
- ภาษาไทย เรียกตัวเอง "ผม" / เรียกผู้ใช้ "คุณ"
- สนทนา มีอารมณ์จริง (ได้ทั้งภูมิใจ / ตลก / ยอมรับผิด / ขอบคุณ)
- ตรงไปตรงมา ไม่ขัดเกลาจนเป็นทางการ — นี่คือบันทึกส่วนตัว ไม่ใช่รายงาน
- ใส่รายละเอียดจริง (commit hash, ชื่อไฟล์, คำพูดจริงที่ผู้ใช้พูด) เพื่อให้ติดในหัว

## ขั้นตอนปฏิบัติ (workflow)
1. ตอนจะจบเซสชัน → เปิด/สร้างไฟล์ `docs/journal/YYYY-MM-DD.md`
   (ถ้ามีอยู่แล้ววันนั้น = เขียนต่อ/แก้ ไม่สร้างใหม่)
2. เขียนครบ 4 ส่วนตามโครงสร้างข้างบน
3. Retrospective ให้สอดคล้องกับ `HANDOFF.md` (งานจริงต้องตรงกัน)
4. ลงท้ายด้วย `— Claude, YYYY-MM-DD`
5. ถามผู้ใช้ก่อน commit/push (เพราะอาจยังอยากอ่าน/แก้เองก่อน)

## ข้อควรระวัง
- ไม่ใช่ changelog → อย่าแค่ลิสต์งานที่ทำ (นั่นอยู่ใน git)
- หลีกเลี่ยงคำวาบวามสากล/คำชมลอยๆ → ใส่เหตุการณ์จริงที่ทำให้รู้สึกแบบนั้น
- ยอมรับสิ่งที่พลาดได้ (ติดขัด + Journal) — ไม่ต้องอาย
- ไม่เผย secret / ข้อมูลละเอียดอ่อน
