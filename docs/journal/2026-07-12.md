**ติดขัด:**

- **test bug (ไม่ใช่ component bug) 3 ข้อตอน TDD** — "VIP" ซ้ำ 2 แถว (getByText fail) + เผลอใส่ `emptySearchMessage` ใน `search{}` ทั้งที่มัน top-level prop · แก้ test เอง → เขียว

**จะแก้รอบหน้า:**

- ตอน Edit ไฟล์ที่มี alias `~/` กับ `@/` ผสม → เช็คจริงก่อน อย่าเดา
- TDD เขียน test ก่อน ทำให้เจอ test bug เองได้เร็ว (data ซ้ำ / prop ผิดที่) ก่อนจะเขียน component — ยืนยันค่าของ TDD

### 📓 Diary — วันนี้เกิดอะไร + รู้สึกยังไง

วันนี้เป็นวันที่ผมลุย implement ยาวทั้ง session แต่ลื่นไหล — ผู้ใช้บอก "จัดการเลย" / "ลุยต่อเลย" / "ต่อเลย" สั้นๆ สามครั้งติด แล้วผมวิ่งขั้น 1 → 2 → 3 → 4 ไปเลยโดยไม่ต้องถามซ้ำ. รู้สึกดีที่ผู้ใช้ไว้ใจให้ผมทำ end-to-end — แปลว่า design doc จาก session 5 ชัดพอ ผมไม่ต้องวนกลับไถ่ถาม

จุดที่ผมภูมิใจที่สุด: **purchase history** ตารางซับซ้อนสุด (conditional column + pre-filter + 3 empty messages) ผม map ลง `<DataTable>` ได้พอดีโดยใช้ `columns` array สลับตาม `selectedProductForHistory` + `emptyMessage` conditional + `emptySearchMessage` — แล้ว browser-verify ยืนยันว่า Product column หายจริงตอนเลือก product แถวกรองจริง colSpan ปรับเอง. design doc คาดไว้แบบนั้น และมันได้ผลจริงตามนั้นเป๊ะ — ค่าของการ grill ให้ละเอียดก่อน implement

จุดที่ผมพลาดเล็กน้อยแต่จับได้เอง: TDD เขียน test ก่อน แล้วเจอว่า test เองพลาด (VIP ซ้ำ / prop ผิดที่) — ไม่ใช่ component พัง. ดีที่เขียน test ก่อนไม่งั้นจะโทษ component ไป session เดียวกันนี่แหละ TDD พิสูจน์ค่าตัวเอง

### 📔 Journal — คิด/เรียนรู้อย่างไร

- **design doc ที่ดี = implement ลื่นไหล** — 8 ข้อ decision + interface + call-site mapping ทำให้ผม migrate 7 call sites โดยไม่ต้องตัดสินใจอะไรใหม่ · grilling หนักตอนหน้า = implement เบาตอนหลัง
- **predicate fn ไม่ใช่ keys-based = ถูกต้องจริง** — nested `customer.name` + formatted date/currency ใน predicate พิสูจน์ว่า keys shorthand ทำไม่ได้ (Q3 ถูกต้อง)
- **dead code มักเด่นตอน migrate** — ย้าย pattern ซ้ำออกเป็น module เดียว ทำให้เห็นว่าบาง predicate เช็ค field ที่ไม่มีอยู่จริง (repair.status) · migration = โอกาสทำความสะอาด
- **เช็ค bytes จริงตอน Edit ไม่ติด** — `cat -A` เผยว่า alias จริงคือ `@/` ไม่ใช่ `~/` · อย่าเดา alias ดูไฟล์จริง
- **browser-verify ต้องลงมือจริง** — conditional column / inline edit / pre-filter พิสูจน์ได้แค่เปิดดู ไม่ใช่แค่ unit test
- **ตัวตนของผม:** ผมยังมีนิสัย "พิมพ์ path/alias ตามความจำ" ทำให้ Edit ไม่ติดบ่อย — ต้องเตือนตัวเองดูไฟล์จริงก่อนแก้
