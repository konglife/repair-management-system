leverage = caller ได้ประโยชน์เยอะต่อ interface ที่ต้องเรียนรู้ · locality = แก้ที่เดียว หาย everywhere
Strong — ควรทำ Worth exploring — ลองดู Speculative — มีก็ดี

C2 · repair pricing: คง residual ไว้ แต่ guard + ตั้งชื่อให้ตรง

Worth exploring in-process
src/server/api/routers/repair.ts:181 · prisma/schema.prisma:118-120
ตัดสินใจแล้ว (ADR-0001): โมเดล residual ถูกต้องสำหรับร้านนี้ — คุณสนแค่ "เก็บเข้ากระเป๋ากี่บาท" ไม่เคยอยากแยก labor กับ markup อะไหล่. C2 เลยไม่ได้เปลี่ยน model. ห้ามเสนอแยก labor/markup ซ้ำ

โมเดล residual คงไว้ · module เดียว guard + เทสได้ไม่ต้องมี DB

ปัญหา: residual margin = totalCost − partsCost ถูกแล้ว แต่ — ฟิลด์ตั้งชื่อ laborCost ทั้งที่จริงคือ margin, ติดลบได้ถ้าพิมพ์ผิด, และการคำนวณอยู่ใน transaction ตัดสต็อก

แนวทาง: module เล็กคง residual ไว้ guard margin ≥ 0 เทสได้ไม่ต้องมี DB ทางเลือก: เปลี่ยนชื่อฟิลด์/concept เป็น margin ในรายงาน

  • guard fat-finger จริงแต่น้อย (0 ใน 530 เคส prod)
  • ตั้งชื่อตรง → หายไปปัญหาสูตร dashboard/reports ต่างกัน (ดู C4)
  • เทสได้ไม่ต้องมี DB; เล็ก
